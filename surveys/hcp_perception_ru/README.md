(09.10: в Q21 добавлены Sinclair (18) и Teoxane Laboratories (19) — попадают в Q22–Q24 и Q29 автоматически;
форма НЯ AE0–AE18 скрыта по просьбе пользователя — AE0 с условием `false`, флаг `AE_ENABLED` в build.py)

(в репозиторий не кладём — конфиденциально). Опрос по ссылке (веб).

- `hcp_perception_ru.json` — анкета для загрузки в SURVEYSTUDIO.
- `build.py` — генератор (`python3 surveys/hcp_perception_ru/build.py`).

## Нумерация

В docx номера вопросов — автонумерация Word, в тексте не сохранились. Восстановлены по порядку и сверены с
перекрёстными ссылками ТЗ: S1.1, S1.2, S1–S3, S3.1, S4–S11, PD; Q1–Q43; AE0–AE18.

Имена переменных = номера ТЗ (`S1_1`, `Q7_1`, `Q15_1_FROM` …). Флаг `GenerateQuestionVariableByTemplate` —
в скриптах обращаемся к вопросам по именам. Номера в системе служебные: скринер 100–116,
основная часть `10000 + q*100 + c*10 + sub`, служебные 9000+, AE 20000+.

## Согласованные решения

- **Блоки «по категориям» развёрнуты генератором в 3 копии** (Q3, Q7–Q13, Q15–Q16, Q18–Q19) — без цикла
  SURVEYSTUDIO, чтобы вопросы по брендам (Q11) были обычным одноуровневым циклом внутри блока.
  Порядок категорий: Q3 — `questions.randomize`, блоки Q7–Q13 — `questions.randomizeGroups`.
- Категории — только с S3 > 0 (Q3, разделы 2–3, Q18, Q34). **Q19 — одна таблица по всем трём категориям**
  (строка = категория, открытое поле, минимум 3 символа), независимо от S3.
- **S3.1** — в категориях с S3 > 0 минимум 1 пациент; мягкое предупреждение, если пациентов больше процедур.
- **Ювидерм** обязателен только в категории 1 (Q9, Q10), даже если не выбран в Q7.
- **Q9** — таблица (строки — характеристики, колонки — бренды Q7 (+ Ювидерм) + «Ни один / не знаю»).
  Автокод «Ни один» для всех строк — только если брендов нет совсем (Q7 = 97 в категории 2/3).
  Если таблица окажется громоздкой — заменить на цикл.
- **Q11** — цикл простых вопросов по брендам с «Увеличится» в Q10 (внутри блока категории).
- **Q14** — при одной категории в S3 колонка «Да, на бренд в другой категории филлеров» скрыта.
- **Q14.1** — таблица; колонки — только категории с S3 > 0; выбор той же категории — ошибка с подсветкой строки.
  При двух категориях ответ вынужден (другая категория) — проставляется автоматически, вопрос не показывается.
- **Q15** — по ТЗ только при переходе в рамках той же категории: два вопроса «Исходный бренд» / «Бренд, на
  который перешли», во втором исходный скрыт (строгая проверка без скрипта). Q16 — при любом «Да» в Q14.
- **Q4** — один раз.
- **Allergan** в Q22 всегда; 0 допускается, только если он не отмечен в Q21 (иначе и остальные — 1–99). При 0 Allergan
  исключается из Q23–Q24. Мягкая проверка >12 — `softWarning()` (повторное «Далее» пропускает).
- **Q29** — по всем компаниям из Q21 + Allergan (решение пользователя 09.10: все компании считаем МНК, отдельного
  списка не будет), порядок компаний случайный.
- **Топ-3 с рангами (Q25, Q27, Q41)** — выбор ровно 3, затем ранжирование выбранных.
- **Q33** — по каждой категории с S3 > 0 три таблицы по брендам, отмеченным в Q7 этой категории (упаковка /
  прейскурант / нетто, цены в рублях), все поля обязательны, «не знаю» = 0 («Если не знаете ответ, впишите 0.»).
  Порядок брендов случайный, одинаковый в трёх таблицах категории. Вопроса о валюте нет (убран в ТЗ 07.10).
- **Форматирование** (жирный/подчёркивание) — как в ТЗ; примечание о торговых марках в S3 — в тексте вопроса.
- **Подстановки «Другое»** — через системный номер вопроса (`{Q12100.96T}`), сборщик заменяет имена сам.
- **Q35/Q36** — таблица мин/сред/макс по категориям из Q34, «не знаю» = 0 («Если не знаете цену, впишите 0.»),
  проверка мин ≤ сред ≤ макс без учёта нулей.
- **Согласие на ПД** — оператор ТОО «АЙКЬЮВИА Солюшнс Казахстан», как в ТЗ 07.10.
- **Q42** — открытое поле. Данные респондента (шапка ТЗ) не собираем.
- Опечатка ТЗ в S8 (продублирован текст S7) исправлена: «К какому типу относится клиника…».
- **S5 (город)** — добавлен вариант «Другой город» (код 96) со скринаутом (по просьбе пользователя, в ТЗ его нет).
- S10, S11, PD: «Нет» / «Не согласен» — продолжаем (ответ сохраняется как пометка). Мягкие квоты по городам —
  счётчиками проекта.
- Строки таблиц перемешиваются скриптом в Подготовке (`rows.randomize()`), а не флагом вопроса — флаг может
  перемешать и колонки-шкалу.
