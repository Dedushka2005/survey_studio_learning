# Aesthetics Market Assessment RU — анкета для SURVEYSTUDIO

Источник: `Aesthetics_Market_Assessment_RU_Quantitative_QNR_V3_Clean_Version.docx`. Формат опроса: веб, по ссылке.

- `aesthetics_ru.json` — готовая анкета. Загружается в SURVEYSTUDIO кнопкой загрузки в списке анкет.
- `build.py` — генератор. Правки вносятся здесь, затем `python3 surveys/aesthetics_ru/build.py`.

## Логика

- Завершение интервью — только скриптами после ответа через глобальные функции (без действий),
  тексты задаются в одном месте:
  - `screenOut()` — результат «Скрининг»: S1 = 3,4; S2 = 1,2; сумма S3 < 15;
  - `refuseOut()` — результат «Завершено»: S0, S7, S8 = «Нет»; в согласии не отмечены пункты 1 и 3.
- S9 и S10 = «Нет» — продолжаем, ответ сохраняется как пометка.
- Раздел 2: категории с S3 > 0 в случайном порядке. В Q9 автоматически отмечаются марки, названные в Q8
  (сопоставление по русским и латинским названиям), список марок — в случайном порядке.
  Q10 — по маркам из Q9. Q11–Q12 — только для марок из списка `NPS_FOLLOWUP` с оценкой 0–6.
- Раздел 3: блок категории задаётся, только если S3 > 0 по этой категории. Порядок марок случайный, но
  одинаковый внутри блока. Суммы процентов контролируются (= 100%).

## Отличия от ТЗ и допущения — требуют подтверждения

1. **Q1, Q3, Q4, Q6 разбиты** на два вопроса: в табличном числовом вопросе SURVEYSTUDIO одна колонка чисел.
   В Q4 вводится только доля новых пациентов, повторные = 100 − новые (итог всегда 100%).
   В Q6 сначала направление, затем % только для «Увеличение/Снижение» («Без изменений» = 0%).
2. **Q3b «Не знаю»** — поле можно оставить пустым (пусто = не знаю).
3. **Q3–Q6 и раздел 3** задаются только по категориям, где в S3 > 0 процедур.
4. **Q11–Q12:** по ТЗ — Ювидерм + до двух марок, выбранных заказчиком. Марки заказчика не указаны, поэтому
   для категорий 2 и 3 списки пустые (вопросы там не задаются). Заполнить `NPS_FOLLOWUP` в `build.py`
   или включить `NPS_FOLLOWUP_ALL = True` — тогда уточнения по всем маркам с оценкой 0–6.
5. **Q11–Q12 — цикл простых вопросов по маркам** (после цикла Q8–Q10 по всем категориям), чтобы «Другое»
   в Q12 уточнялось сразу в вопросе. В ТЗ они стоят внутри каждой категории; цикл внутри цикла не делаем —
   в SURVEYSTUDIO в таких вопросах не выполняются их собственные скрипты.
6. **Q16/Q24/Q32** — в выпадающем списке марки с долей > 0 в Q13/Q21/Q29.
   **Q17/Q25/Q33** — известные марки (Q9 + используемые) и «Ни одна из марок / Не знаю».
   Если фильтрация выпадающего списка не сработает в системе, будут показаны все марки категории.
7. **Q18/Q26/Q34** — в ТЗ у таблицы колонка «Ни одна из марок / Не знаю» (похоже на опечатку шаблона);
   сделан вопрос с одним выбором и вариантом «Не знаю».
8. **Плинест** (код 29) есть в Q21, но отсутствует в приложении со списком марок — оставлен.
9. Тексты «Рекрутер, зачитайте…» переписаны для самозаполнения; сумма компенсации и телефон для обращений
   оставлены как `____` / `___`, как в ТЗ.
10. Контактные данные и согласие собираются после S10 (в ТЗ — таблица «Данные респондента» в начале, которую
    заполняет рекрутер).

## Что проверить при первом тесте

- Анкета загружается без ошибок (формат собран по описанию из базы знаний, живой загрузкой не проверялся).
- Статусы завершения («Скрининг», «Завершено») в режиме тестирования.
- Работа цикла раздела 2 и подстановка названия категории `{answerText}`.
- Выпадающие списки в Q16/Q17 (см. п. 6).
