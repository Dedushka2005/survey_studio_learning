## Структура и нумерация

| Блок | Номера | Имена |
|---|---|---|
| Скринер S0–S9, согласие на ПД | 100–112 | `S0` … `S9`, `PD` |
| Раздел 1 (Q1–Q7) | 10100–10799 | `Q1a`, `Q1b`, `Q2`, `Q3a`, `Q3b`, `Q4_new`, `Q4_rep`, `Q5`, `Q6_dir`, `Q6_pct`, `Q7` |
| Вводный экран раздела 2 | 9100 | `INFO2` (список только категорий с S3 > 0) |
| Раздел 2 по категориям c = 1..3 | `10000 + q·100 + c·10` | `Q8_c`, `Q9_c`, `Q10_c`, `Q11_c_{3}`, `Q12_c_{3}` |
| Служебные | 9101, 9111–9113 | `Categories` (названия категорий), `SVC11_c` (бренды для Q11–Q12) |

показывается только при S3 > 0 по этой категории (`Q105(row = c and valueNum > 0)`).

## Проект (поле): CAWI по персональным ссылкам, квоты город × тип (15.10.2026)

- **Ссылки:** `https://sst.gl/algsh1026?extid=<ID>`, 7000 шт. — `links/aesthetics_ru_v2_links_7000.xlsx`
  (`tools/make_links.py https://sst.gl/algsh1026 7000 … --types 1:3500,2:3500`; **не перегенерировать** — новые ID
  не совпадут с базой). Rid 1–3500 — тип 1 (личный опрос), Rid 3501–7000 — тип 2 (CAWI).
- **База контактов** — тот же xlsx: `Rid`, `type` — «Поле с данными», `ID` — «Внешний ключ», `Телефон` — «Телефон»
  (фиктивный), `Ссылка` — «Пропустить».
- **Служебные вопросы** перед S0: `Rid` (10, Numeric) и `Type` (11, единственный выбор: 1 — Личный опрос, 2 — CAWI)
  заполняются из базы (`add_rid`, `add_contact_choice`); нет контакта / типа → «Ссылка на опрос недействительна…».
  Тип на анкету не влияет, только для квот.
- **Квоты** — город S4 (номер 106, 36 городов) × тип (номер 11): вложенные счётчики — город `Q106 = <код>` (флаг
  «Учитывать только полные интервью»), внутри «Личный опрос» `Q11 = 1` и «CAWI» `Q11 = 2` с квотами; или плоские
  `Q106 = 1 and Q11 = 1 and Result = Completed` / условие квоты `Q106 = 1 and Q11 = 1`.
  Текст при закрытой квоте — в «Обработке». Флаги проекта — как в HCP (README hcp_perception_ru, «Проект (поле)»).
- Тест ссылок — в «Сбор данных», ссылками с конца каждого типа (Rid 3491–3500 и 6991–7000), их не рассылать.

## Решения по ответам пользователя

- Скринауты — `screenOut()` (результат «Скрининг»), отказы — `refuseOut()`. Данные о не прошедших отбор не собираем.
- S3: строки категорий + «Джувелук», 0–9999, сумма < 15 → скрининг; сноска о товарных знаках в тексте.
- S4: обычный одиночный выбор городов в 3 колонки (36 городов; как S5 в HCP Perception, там 2 колонки) + «Другой город» → скрининг. S7: код 1 → скрининг.
- S8 — без примечания о повторном контакте; S9 (13.10.2026) — вместо текста о НЯ вопрос о согласии на повторный контакт, «Нет» — продолжаем (пометка = ответ «Нет» в данных). ПД: «Не согласен» — продолжаем; юрлицо ТОО «АЙКЬЮВИА Солюшнс Казахстан».
- Q1a 0–99999; по категориям 1–3 при S3 > 0 ответ 0 — ошибка с подсветкой строки (13.10.2026); Q2 + «Не знаю»; Q3 «Не знаю» только для «4 года назад» — вводом 0 с инструкцией.
- Q4: вводится доля новых пациентов, повторные = 100 − новые (служебно, не показываем). Q5 целые числа.
- Q7: «Другое» необязательное, при числе требуется текст (и наоборот).
- Q8: обязательно хотя бы одно упоминание. Спонтанные упоминания в Q9 автоматически не переносим.
- Q10: бренды, отмеченные в Q9, + «Другое» из Q9 (текст подставляется макросом `{Q109c0.96T}`).
- Q11–Q12: в каждой категории — цикл по служебному `SVC11_c`. Кат.1: Ювидерм (если оценка 0–6) + 2 случайных
  бренда с оценкой 0–6; кат.2/3: 2 случайных бренда с оценкой 0–6. Q12 — не более 3 факторов, «Другое» с полем.
  Если вернуться назад и изменить оценки, ранее выбранные бренды сохраняются, пока они остаются в 0–6.
- Раздел 3: строки долей — бренды из Q9 (+ «Другое» из Q9), один бренд — 100% автоматически; проверка суммы
  ошибкой. Q16 (области × бренды): колонки — бренды с долей > 0, один бренд — проставляется автоматически.
  Q17 (сценарии): колонки — бренды из Q9; если в Q9 «Ничего из перечисленного» — автоматически «Не знаю».
  Строка 9 сценариев — только у биоревитализантов. Мягких проверок цен нет. Коды «Другое» везде 96.
- AE11: при AE10 = «Я сам(а)» текст меняется на «Укажите Ваш пол». AE0 = «Нет» — завершение.
- **Форма НЯ AE0–AE18 скрыта** (09.10.2026, просьба пользователя): AE0 с условием `false`, весь блок не
  показывается, интервью завершается как полное. Вернуть — `AE_ENABLED = True` в build.py.

## Допущения (уточнить у пользователя)

  тоже только при оценке 0–6; если нужен всегда — `JUVEDERM_ANY_SCORE = True` в build.py
