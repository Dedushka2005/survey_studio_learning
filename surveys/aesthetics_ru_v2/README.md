## Структура и нумерация

| Блок | Номера | Имена |
|---|---|---|
| Скринер S0–S9, согласие на ПД | 100–112 | `S0` … `S9`, `PD` |
| Раздел 1 (Q1–Q7) | 10100–10799 | `Q1a`, `Q1b`, `Q2`, `Q3a`, `Q3b`, `Q4_new`, `Q4_rep`, `Q5`, `Q6_dir`, `Q6_pct`, `Q7` |

Категории не циклом SURVEYSTUDIO, а развёрнуты генератором (чтобы не было цикла в цикле). Каждый блок категории
показывается только при S3 > 0 по этой категории (`Q105(row = c and valueNum > 0)`).

## Решения по ответам пользователя

- Скринауты — `screenOut()` (результат «Скрининг»), отказы — `refuseOut()`. Данные о не прошедших отбор не собираем.
- S3: строки категорий + «Джувелук», 0–9999, сумма < 15 → скрининг; сноска о товарных знаках в тексте.
- S4: обычный одиночный выбор городов в 2 колонки (как S5 в HCP Perception) + «Другой город» → скрининг. S7: код 1 → скрининг.
- S8: текст о повторном контакте — обычным текстом. ПД: «Не согласен» — продолжаем; юрлицо ТОО «АЙКЬЮВИА Солюшнс Казахстан».
- Q1a 0–99999; Q2 + «Не знаю»; Q3 «Не знаю» только для «4 года назад» — вводом 0 с инструкцией.
- Q4: вводится доля новых пациентов, повторные = 100 − новые (служебно, не показываем). Q5 целые числа.
- Q7: «Другое» необязательное, при числе требуется текст (и наоборот).
- Q8: обязательно хотя бы одно упоминание. Спонтанные упоминания в Q9 автоматически не переносим.
- Q10: бренды, отмеченные в Q9, + «Другое» из Q9 (текст подставляется макросом `{Q109c0.96T}`).
- Q11–Q12: в каждой категории — цикл по служебному `SVC11_c`. Кат.1: Ювидерм (если оценка 0–6) + 2 случайных
  бренда с оценкой 0–6; кат.2/3: 2 случайных бренда с оценкой 0–6. Q12 — не более 3 факторов, «Другое» с полем.
  Если вернуться назад и изменить оценки, ранее выбранные бренды сохраняются, пока они остаются в 0–6.
- Раздел 3: строки долей — бренды из Q9 (+ «Другое» из Q9), один бренд — 100% автоматически; проверка суммы
  ошибкой. Q16 (области × бренды): колонки — бренды с долей > 0, один бренд — проставляется автоматически.
  Q17 (сценарии): колонки — бренды из Q9; если в Q9 «Ничего из перечисленного» — автоматически «Не знаю».
  Строка 9 сценариев — только у биоревитализантов. Мягких проверок цен нет. Коды «Другое» везде 96.
- AE11: при AE10 = «Я сам(а)» текст меняется на «Укажите Ваш пол». AE0 = «Нет» — завершение.

## Допущения (уточнить у пользователя)

- «Оценка 0–6 в Q9» понята как оценка рекомендации в **Q10** (в Q9 оценок нет). Ювидерм попадает в Q11–Q12
  тоже только при оценке 0–6; если нужен всегда — `JUVEDERM_ANY_SCORE = True` в build.py
  (тогда при оценке 7–10 Q11 пропускается, Q12 задаётся).
- Порядок категорий случайный и одинаковый в разделах 2 и 3 — через `setOrderGroups` (⚠️ не проверено).
- Порядок брендов в разделе 3 — один случайный внутри блока категории (доли, мл, Q16, Q17).

## Что проверить при тесте

1. INFO2 перечисляет только категории с S3 > 0 и в том порядке, в котором идут блоки.
2. Порядок блоков категорий в разделе 3 совпадает с разделом 2 (`setOrderGroups`).
3. Q11–Q12: в кат.1 Ювидерм + до 2 брендов с оценкой 0–6; в тексте Q11 подставляются бренд и оценка;
   «Другое» из Q9 показывается вписанным текстом.
4. Раздел 3: автоматическое 100% при одном бренде, автокод Q16 при одном бренде, Q17 при «Ничего» в Q9.
5. Подстановки «Другое» (`{Q….96T}`) в Q10 и Q16.
6. Скринауты: S1.1, S1.2, S1, S2, S3 < 15, S4 «Другой город», S7; отказы S0, S8.
