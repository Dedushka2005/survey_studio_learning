# SURVEYSTUDIO — шпаргалка по программированию анкет

Конспект базы знаний https://kb.surveystudio.ru/ (скачать заново: `python3 tools/fetch_kb.py`, страницы
сохраняются в `kb/`, эта папка не коммитится).

## 1. Три уровня логики

| Уровень | Где задаётся | Для чего |
|---|---|---|
| Условие показа | свойство вопроса `Condition` | показать/не показать вопрос |
| Действия | «Перед показом» / «После ответа» | переходы, скрытие ответов, переменные, ошибки, завершение |
| Скрипты (JavaScript) | глобальные и у вопроса | всё, что не решается первыми двумя |

Действия выполняются по порядку, пока одно не вернёт окончательный результат (переход, завершение, ошибка).

## 2. Синтаксис выражений (условия показа, действий, счётчиков, квот)

- Операторы: `=  !=  >  <  >=  <=`, `and or not`, скобки.
- Ключевые слова: `code`, `row`, `valueTxt`, `valueNum`, `valueInt`, `null`.
- `Q` без номера — текущий вопрос (рекомендуется в «после ответа»).
- Всегда истинно: `1 = 1`, `any`, `all`. Никогда: `false`, `1 = 2`.

```
Q1 = 2                          выбран код 2
Q1(code = 1 or code = 3)        выбран 1 или 3 (предпочтительнее, чем Q1=1 or Q1=3)
Q1(code >= 1 and code <= 5)     код в диапазоне
Q1(code = 98 and valueTxt != null)   выбран 98 и заполнено «другое»
Q1(valueNum >= 18 and valueNum <= 35) числовой вопрос в диапазоне
Q1(row = 1 and code = 4)        таблица: в строке 1 выбран код 4
not Q1 != 99                    таблица: во всех строках выбран 99
Q1 and not Q1 = 3               вопрос отвечен и код 3 НЕ выбран
Q = 3 and not Q != 3            выбран ТОЛЬКО код 3
```

**Ловушка `!=`:** `Q1 != 3` означает «есть ли ответ с кодом ≠ 3». Для множественного выбора
это почти всегда не то. Правильно — `Q1 and not Q1 = 3`.

Сравнение `valueTxt` только по точному совпадению (регистр и пробелы важны).

**Ловушка `valueNum` в вопросе с выбором:** `Q108(valueNum = 1)` — это «в открытом числовом поле ответа
вписано 1», а не «выбран код 1» (`kb/help_questionnaires_1006.md`). Выбор кода — `Q108 = 1` / `Q108(code = 1)`
(квоты HCP, 15.10.2026).

## 3. Подстановки в тексты

- `{Q1}` — текст выбранного ответа (для «другое» — вписанный текст; несколько — через запятую).
- `{Q5.1N}` / `{Q5.98T}` — число/текст из открытого поля ответа (или строки таблицы).
- `{Q5.1}` — значение строки 1 табличного текстового/числового вопроса.
- `{Q5.1.2N}` — число поля ответа 2 в строке 1 таблицы с выбором.
- `{ИмяПеременной}` — значение из `variables` (действие «Установить значение переменной» или `V.x = ...`).
- В циклах: `{answerText}`, `{answerCode}`.

## 4. Основные действия (ActionType в файле анкеты)

Переходы: `JumpToQuestion`(N1=номер), `JumpToEnd`(T1=текст, N1=результат), `Skip`, `SkipIfNoVisible`,
`SkipIfVisibleNoMoreThan`(N1), `Answered`, `AnsweredOrSkip`, `ReturnError`(T1=текст), `ResetAnswers`,
`CopyAnswersFromQuestion`(N1), `ChooseFirstVisibleAnswer`(N1), `FillAnswerFromParameter`, `LoadAnswersFromContactData`.

Ответы: `HideAll`, `HideCodes`(T1="2,5,6"), `HideOnlyCodes`, `HideCheckedInQuestion`(N1),
`HideOnlyCheckedInQuestion`, `HideFromTo`(N1,N2), `ShowAll`, `ShowCodes`, `ShowOnlyCodes`,
`ShowCheckedInQuestion`(N1), `ShowOnlyCheckedInQuestion`(N1), `ShowFromTo`(N1,N2) …
Для строк — префикс `Rows…`, для колонок — `Columns…`.

Переменные: `SetVariableValue`(T1=имя, T2=значение), `SetVariableValueFromOpenValue`(T1=имя, N2=вопрос, T2=код),
`SetVariableValueFromContactData`(T1=имя, T2=поле).

## 5. Скрипты

Типы: **Подготовка** (один раз при старте и при выгрузке; только структура: создание/порядок вопросов,
циклы, флаги; не логика!), **Обработка** (после завершения, перед записью), **Перед показом**,
**После ответа** (глобальные — выполняются до скриптов вопроса), **Функции** (общие функции),
**Во время показа** (в браузере, без API), **CSS**.

Пишется только тело функции; параметр `Q` — текущий вопрос.

Возвращаемые значения:
```js
return ok;            // ничего особенного
return skip;          // (перед показом) сбросить и пропустить
return answered;      // (перед показом) ответ проставлен скриптом, не показывать
return error('Текст');// (после ответа) показать вопрос снова с ошибкой
return question(123); // переход на Q123
return exit('Спасибо');                                  // завершить (Завершено)
return exitWithResult(InterviewResult.Screening, 'Текст'); // скринаут
return exitAndRedirect('Текст', 'https://...');
```
`InterviewResult`: Completed, Screening, Overquoting, Defect, Interrupted, Postponed, Exited, Unknown.

### Доступ к данным
```js
Q1, questions[34]              // вопрос
Q1[5].checked / Q1.answers[5]  // ответ с кодом 5
Q1.isChecked(5)                // выбран ли код 5
Q1.getCheckedCode()            // код (единств. выбор), 0 если нет
Q1.getCheckedCodes()           // массив кодов
Q1.getChecked()                // массив объектов-ответов
Q1.openValueNum / openValueInt / openValueTxt   // числовой/текстовый вопрос
Q1[98].openValueTxt            // «другое»
Q1.isAnswered
Q2.rows[3].getCheckedCode()    // таблица
calc('Q1(code = 1 or code = 3)')  // выражение из п.2 внутри скрипта
V.name = '...'; variables['ФИО']  // глобальные переменные (только простые типы)
parameters.city                // параметр ссылки
contact.data['Поле']           // база контактов
getCounter('Имя') -> {value, quota}
isTesting(), isPostProcessing(), isValidation(), isRedial()
```

### Управление ответами (то же для `rows`, `columns`)
```js
Q.hideAll(); Q.show(1, [3,5]); Q.showOnly(Q1.getCheckedCodes()); Q.hide(99);
Q.showFromTo(1, 10); Q.visibleCount; Q.hasVisible
Q.answers.randomize(); Q.answers.rotate(); Q.answers.randomizeGroups([[1,3],[4,6]]);
Q.answers.setOrder(Q1.answers.getCodes());   // тот же порядок, что в Q1
Q.answers.add(99, 'Не знаю').settings.blocking = true;
Q.reset();
```

### Вопросы (в Подготовке)
```js
questions.randomize([1,3,5]); questions.rotateFromTo(10, 20);
questions.randomizeGroups([[1,2],[3,8],[9,9]]);
questions.repeat(2, 3, 1);        // цикл: Q2–Q3 для каждого выбранного в Q1
questions.repeatIfNot(2, 3, 1);   // для невыбранных
```
Цикл пересоздаёт вопросы с номерами «исходный номер + код ответа» (Q201, Q298 …; разрядность по максимальному коду).
Внутри цикла: `Q.sourceAnswerCode`, `Q.sourceQuestionNumber`, `Q.currentIterationQuestions[2]`.
Обычные условия показа по вопросам цикла не работают — используйте скрипты перед показом.
Ответу, который не должен порождать итерацию (например «Никакими»), ставится флаг «Запрещено использовать в циклах».

## 6. Типовые приёмы

- **Скринаут:** действие после ответа `JumpToEnd` с условием, либо `return exitWithResult(InterviewResult.Screening)`.
- **Показать только выбранные ранее:** действие `ShowOnlyCheckedInQuestion` (N1 = номер) + `SkipIfNoVisible`.
- **Автокодирование возраста** (перед показом вопроса-группы):
  ```js
  let age = Q1.openValueInt;
  Q[1].checked = age <= 17; Q[2].checked = age >= 18 && age <= 24; /* … */
  return answered;
  ```
- **Сумма = 100** в таблице чисел: свойства `AnswersSumControlTarget = 100`, `AnswersSumControlMode = Exactly`.
- **Исключающий ответ** («Затрудняюсь ответить»): флаг ответа `Blocking`.
- **Необязательный вопрос:** флаг `CanSkip` (при «Пропустить» действия/скрипты после ответа не выполняются).
- **Собственная проверка:** флаг `CustomValidation` + скрипт после ответа с `return error(...)`.
- **Служебный вопрос:** условие показа `false`, флаг `SkipExport`.
- **Нельзя переходить к вопросу, который перемешивается с другими** — остальные из группы будут пропущены.

- **Оформление (kb cawi/3014):** 1) **Тема** — Настройки → Темы → Добавить: цвета в редакторе (HEX/RGBA),
  предпросмотр; тему выбирают в свойствах анкеты/проекта (или по умолчанию для аккаунта — звезда).
  Изменения применяются с задержкой до 30 с. 2) **CSS** (Скрипты → CSS, в файле `ScriptCSS`, в генераторе
  `qnr.css`) — только через поддерживаемые атрибуты `[data-part='…']` (survey, progress, question-text,
  question-comment, answer, answer-text, marker, table, row, cell, column-header …), остальные классы не
  гарантируются. В CAPI (планшет) CSS не работает.
  Подбор цветов темы — отложен пользователем (09.10.2026). Если заказчик в анкете не раскрывается
  (HCP Perception), его фирменные цвета не используем — нейтральная палитра или цвета агентства.

### Проект CAWI по персональным ссылкам и квоты (по базе знаний, HCP и Aesthetics v2 15.10.2026; ✅ проверено тестом живых ссылок)

**Порядок запуска проекта (HCP, Aesthetics v2 — 15.10.2026):**
1. Анкета: `qnr.add_rid()`, при квотах по типу — `qnr.add_contact_choice(…)`, `qnr.add_overquota_text()` (в шаблоне
   уже есть). Логику проверить бесплатно — тестовый запуск / проект в «Разработке».
2. Проект «Веб-опрос», загрузить анкету, задать короткую ссылку (`sst.gl/<имя>`).
3. Ссылки: `tools/make_links.py <короткая ссылка> N links/<анкета>_links_N.xlsx [--types 1:…,2:…]` — файл
   коммитим в папку анкеты (`surveys/<анкета>/links/`) и больше **не перегенерируем**.
4. Тот же xlsx — в базу контактов (флаг «Поля с дополнительными данными»): Rid/type — «Поле с данными»,
   ID — «Внешний ключ», Телефон — «Телефон», Ссылка — «Пропустить».
5. Флаги проекта: запрет без extid, запрет без контакта по extId, «Защита от переполнения квот»; «Время жизни
   брошенных интервью» 10–15 мин.
6. Счётчики/квоты: выбор кода — `Q<номер> = код` (**не** `valueNum`), в «Условии» + `and Result = Completed`, в
   «Условии квоты» — без статуса. Две ячейки на город (город × тип) — вложенные счётчики.
7. Баланс → «Сбор данных» → тест ссылками с конца файла (не рассылать) → удалить тестовые интервью → рассылка.


- **Персональная ссылка** = рабочая ссылка + `?extid=<ID>` (`kb/cawi_3011.md`). ID до 64 символов, лучше
  случайный, чтобы не подобрать. По той же ссылке можно прервать и продолжить (с первого неотвеченного,
  с любого устройства), пока проект в «Сбор данных» и у интервью нет конечного результата; после
  завершения повторно не заполнить. В скриптах — `respondent.extId`.
- Флаги проекта: «Запрещать запуск анкеты, если отсутствует уникальный идентификатор контакта»; при
  загруженной базе контактов — «Запрещать запуск анкеты, если в базе не найден контакт по extId» (защита от
  выдуманных ID). База: столбец ID (тип «Внешний ключ») + телефон (можно любые ≥ 5 цифр); доп. поля — в
  выгрузку флагом «Выгружать дополнительные поля…», в анкете — `contact.data['Поле']`.
- Другие параметры ссылки (`&city=3`) — `parameters.city`, в массив флагом «Выгружать параметры из ссылки»
  (`kb/cawi_3059.md`).
- **Квота — счётчик проекта** (`kb/howto_1007.md`): «Условие» — что считать среди сохранённых
  (`Q108 = 1 and Result = Completed`), «Условие квоты» — проверка во время интервью, без статуса (`Q108 = 1`),
  чтобы квота срабатывала сразу после квотного вопроса, «Квота» — число. Сверх квоты интервью по умолчанию
  не сохраняется (можно включить — статус Overquoting, `kb/howto_1016.md`). Счётчики можно менять во время поля.
- **Свой текст при закрытой квоте** — скрипт «Обработка» (`qnr.postprocessing`):
  `if (interview.result == InterviewResult.Overquoting) return exit('…');` (`kb/help_scripts_2999.md`).
- **Простой номер респондента** при случайных ID (HCP, 15.10.2026): `tools/make_links.py` даёт xlsx — он же база
  контактов (Rid — поле с данными, ID — внешний ключ, фиктивный телефон); скрытый Numeric-вопрос «Rid» перед
  показом пишет `contact.data['Rid']` и возвращает `answered`. `contact` проверять через `typeof` (без базы
  объекта может не быть). Своя база + флаг «не найден контакт по extId» — защита от выдуманных ID.
- **Короткая ссылка** — свойства проекта, поле «Короткая ссылка» (`kb/cawi_3017.md`), параметры — после `?`:
  `https://sst.gl/algln1026?extid=…` (HCP). Обе ссылки равнозначны.
- **Состояние проекта «Разработка»** — анкета работает в режиме тестирования, **ответы не сохраняются**
  (`kb/help_projects_3001.md`), `isTesting()` = true («без проекта, т.е. без сохранения интервью в базу»).
  - Можно проверить: логику и тексты анкеты (переходы, скринауты, циклы, проверки), что ссылка открывается.
  - Нельзя: Rid (скрипт в тестировании без контакта пропускает вопрос — пустой Rid ничего не значит), отсечку
    ссылки без ID / с выдуманным ID (скрипт в тестировании не отсекает, сработают ли флаги — в базе знаний не
    сказано), одноразовость и продолжение по той же ссылке (интервью не сохраняется), квоты и текст при квоте
    (счётчики считают сохранённые интервью).
- **Тест ссылок — в «Сбор данных»**, до рассылки (чтобы в массив/счётчики не попали чужие интервью):
  ссылки с конца файла (HCP: Rid 4991–5000), их не рассылать. Чек-лист: Rid в массиве = номеру из файла;
  прервать и открыть ту же ссылку в другом браузере — продолжение; после завершения не пускает; без `?extid` и
  с изменённым ID не пускает; квота 0 у одного города → наш текст сразу после квотного вопроса (потом вернуть
  число); скринаут работает. Сохранённые интервью оплачиваются (нужен баланс, иначе проект «Приостановлен»).
  После теста удалить тестовые интервью (освобождается ли при этом extid — ⚠️ не проверено, поэтому тестовые
  ссылки не рассылаем).
- **Ручная вставка Rid в запущенную анкету** (без перезагрузки): новый вопрос «Числовой» первым, шаблон имени
  `Rid`, диапазон 1–99999, скрипт `RID_SCRIPT` в поле **«Перед показом»** (не «Во время показа» — там нет
  `contact`); номер система может дать свой (HCP — 10), потом привести build.py к выгрузке. ✅ внесено, выгрузка
  совпала (HCP, 15.10.2026); работу в поле — ⚠️ проверить тестом ссылок.
- **Ручная вставка Type** (Aesthetics v2): «Единственный выбор» вторым после Rid, шаблон имени `Type`, варианты
  1/2 **без `<p>`** (система при вводе обернула — подписи пошли бы в массив), скрипт из `add_contact_choice()` в
  «Перед показом». Список система назвала «QType список» — в build.py `list_name='QType список'`. ✅ выгрузка
  совпала (номера 10/11 сохранились).
- **Тест живых ссылок, Aesthetics v2 (15.10.2026):** ✅ Rid и Type из базы контактов пишутся в интервью (видно в
  просмотре); ✅ скринаут сохраняется (статус «Скрининг»); ✅ дошли до конца — сохранилось «Полное».
  ✅ **Значения счётчиков на странице статистики обновляются кнопкой `Расчёт значений`** (она же обновляет общую
  статистику, `kb/help_projects_3002.md`) — сразу после интервью полное в квотах может быть не видно. Проверка
  квоты во время интервью от этой кнопки не зависит: система сама считает сохранённые интервью в базе
  (`kb/howto_1007.md`). Ещё задержка: брошенная (не дошедшая до прощального текста) анкета сохраняется и
  попадает в статистику только по истечении «Времени жизни брошенных интервью» (по умолчанию 3 ч).
  ✅ Флаги проекта отсекают сами (до нашего скрипта Rid): без `extid` — «Отсутствует идентификатор контакта в
  параметре запроса»; выдуманный ID — «Упс... Запрашиваемый контакт не найден. Обратитесь к организатору опроса.»;
  повторно по завершённой ссылке — «Вы уже проходили этот опрос. Спасибо за участие!» (тексты системные).
  ✅ Закрытая квота — наш текст из «Обработки» («К сожалению, мы уже набрали…»).

  браузер) — анкету можно дозаполнить. Значит, короткое время жизни безопасно: врач не теряет анкету, а место в
  квоте и статистика освобождаются/обновляются быстро. Рекомендуем 10–15 мин (Aesthetics v2, 15.10.2026).
- **Короткие проверки для теста ссылок** (почти бесплатно): Rid + одноразовость — отказ в S0, затем открыть ссылку
  снова; продолжение — пара ответов, закрыть, открыть в другом браузере, завершить отказом; квота — квота 0 у
  города, выбрать его (сверх квоты не сохраняется); без ID / с изменённым ID — не должно пустить. Целиком анкету
  проходить не нужно — логика проверена в тестовом режиме.
- **Деньги на балансе** — сбор данных платный (`kb/start_1008.md`, `kb/help_5000.md`): на балансе личного
  кабинета должна быть достаточная сумма, иначе во время поля проект станет «Приостановлен» и новые интервью не
  начнутся (`kb/start_1009.md`). Оплачиваются ответы / сохранённые интервью; в «Расход за месяц» входит и выгрузка
  интервью. Тест в «Разработке» бесплатный (не сохраняется). Вместо пополнения картой (Финансы → `Пополнить`,
  ЮKassa) для юрлица/ИП — кредитный лимит: счёт в начале месяца, оплата до 20 числа.

## 7. Формат файла анкеты (импорт/экспорт, JSON, UTF‑8)

```json
{
  "Magic": "SS2EQN", "Version": "2.4", "Name": "Анкета",
  "ExportedQuestionnaireFlags": {}, "ExportedSurveyFlags": {},
  "ScriptPreProcessing": "questions.repeat(2, 3, 1);",
  "Questions": [
    { "OrderIdx": 1, "Number": 1, "Text": "Ваш пол?", "QuestionType": "SingleChoice",
      "ExportedQuestionFlags": {}, "ExportedSurveyFlags": {}, "AnswerList": "Пол",
      "AfterAnswerActions": [
        { "OrderIdx": 1, "Condition": "Q = 3", "ActionType": "JumpToEnd",
          "ActionVarTxt1": "Спасибо!" } ] }
  ],
  "AnswerLists": [
    { "Name": "Пол", "Type": "Common", "AnswerItems": [
      { "OrderIdx": 1, "Code": 1, "Text": "Мужской", "ExportedFlags": {} },
      { "OrderIdx": 2, "Code": 2, "Text": "Женский", "ExportedFlags": {} } ] }
  ]
}
```
Обязательно у вопроса: `OrderIdx, Number, Text, QuestionType, ExportedQuestionFlags, ExportedSurveyFlags`.
Типы: Information, WelcomeScreen, Text, Numeric, Phone, Email, DateTime, SingleChoice, MultipleChoice,
Dropdown_SingleChoice, Dropdown_MultipleChoice, Ranking, Rating, Slider, MaxDiff, SemanticDifferential,
Table_Text, Table_Numeric, Table_SingleChoice, Table_MultipleChoice, Table_Dropdown_SingleChoice, Table_Rating, Table_Slider …
Поля вопроса: `Condition, Comment, AnswerList, RowList, ColumnList, MinAnswerCount, MaxAnswerCount,
AnswerNumberFrom, AnswerNumberTo, ScriptBeforeShow, ScriptAfterAnswer, BeforeShowActions, AfterAnswerActions, OutputColumnTemplate`.
Флаги ответа: `OpenValueNum, OpenValueTxt, Blocking, AlwaysVisible, DisableReordering, DisableRepeat, GroupHeader, SkipExport`.
Флаги вопроса: `RandomizeAnswers, RotateAnswers, CanSkip, CustomValidation, SkipExport, ShowRowsOneByOne`.

Значит, анкету можно собрать целиком в JSON и загрузить в систему одним файлом.

## 8. Наши соглашения (обязательно соблюдать)

- **Город практики — обычный одиночный выбор** (`SingleChoice`, `ColumnCount` 2–3 по длине списка), не выпадающий список —
  одинаково во всех анкетах (просьба пользователя 09.10.2026).
- **Завершение интервью — только скриптом после ответа через глобальные функции**, не действием
  «Завершить интервью» (там текст пришлось бы прописывать в каждом вопросе). В «Функциях» анкеты:
  ```js
  function screenOut() {   // не подходит по критериям -> «Скрининг»
      return exitWithResult(InterviewResult.Screening, 'Благодарим вас… не можете принять участие.');
  }
  function refuseOut() {   // отказ от участия -> «Завершено»
      return exitWithResult(InterviewResult.Exited, 'Благодарим вас за уделенное время! До свидания.');
  }
  ```
  В вопросе: `if (Q.isChecked(3) || Q.isChecked(4)) return screenOut();`

  обновлённый JSON файлом** (он импортирует его в SURVEYSTUDIO), в README анкеты — пункт проверки в TODO.

- **Свойства анкеты по умолчанию** (в `Questionnaire`): включено «Запускать опрос в новой веб-дате»
  (`RunInNewService`), «Скрыть номера вопросов» выключено (`HideQuestionNumbers: False`), коды ответов скрыты.
- **Форматирование текста — как в ТЗ:** жирный/подчёркивание переносим в те же фразы (`<b>`, `<u>`); свои
  выделения не добавляем (кроме служебных подписей «Категория: …», «Компания: …» и заголовков разделов).
  Выделения в docx удобно вытащить скриптом по `w:b`/`w:u` в `word/document.xml`.
- **Мультивыбор с «Другое (укажите)» по нескольким объектам — не таблицей**, а циклом простых вопросов
  (в таблице у колонки «Другое» нет поля для текста, уточнение пришлось бы выносить на отдельный экран).
- **Строка «Другое (укажите)» в таблице с выбором — всегда так** (стандарт с 12.10.2026, проверено в HCP Q8):
  строка `{96: OTHER_CHOICE_ROW}` (необязательная, с текстом, не перемешивается) + скрипт после ответа:
  - **один ответ в строке** (`Table_SingleChoice`) — `after='return otherChoiceRow(Q, 96);'` (ниже);
  - **несколько ответов** (`Table_MultipleChoice`) — `after='return requireChoiceRowText(Q, 96);'`: галочку
    респондент снимает сам, поэтому без предупреждений — ответ без текста или текст без ответа = ошибка
    (⚠️ снятие галочки в таблице повторным кликом в системе не проверяли — проверить при первой такой таблице).

  Для одного ответа: Логика: текст без ответа — ошибка «дайте ответ в строке»;
  ответ без текста — первое «Далее» предупреждает «Вы не вписали свой вариант… ответ в этой строке будет
  удален», повторное «Далее» снимает отметку на сервере (радиокнопку в таблице респондент сам не снимет).
  `save()` падает, если в таблице с выбором есть строка с текстом без нужного скрипта или строка обязательная.
  Другие проверки в том же вопросе — раньше, `return otherChoiceRow(Q, 96);` — последней строкой.
  Для ручной вставки в систему (без функции в «Функциях») — самодостаточный вариант:
  ```js
  let row = Q.rows[96];
  if (row === undefined || !row.visible) return ok;
  if (isPostProcessing() || isValidation()) return ok;
  let key = 'otherRow_' + Q.number + '_96';
  let checked = row.getCheckedCodes();
  if (row.openValueTxt) {
      V[key] = '';
      if (checked.length === 0) return error('Пожалуйста, дайте ответ в строке «Другое»');
      return ok;
  }
  if (checked.length === 0) { V[key] = ''; return ok; }
  if (V[key] !== checked.join(',')) {
      V[key] = checked.join(',');
      return error('Вы не вписали свой вариант в строке «Другое». '
          + 'Если нажмете «Далее», ответ в этой строке будет удален.');
  }
  V[key] = '';
  for (let c of checked) row[c].checked = false;
  return ok;
  ```
- Числовые границы задаём по смыслу, с запасом (мл, штуки — до 9999), а не «до 100» по умолчанию.
- Строку «Прочее (укажите)» в числовой таблице делаем необязательной (`CustomRowValidation` + `AllowEmptyOpenValue`)
  и проверяем `requireRowText()`: число без текста или текст без числа — ошибка.
- Заголовки разделов с вводным текстом — отдельным информационным экраном, а не шапкой каждого вопроса.
- **Автоответ при единственном варианте:** если после фильтра остался один вариант (или одна строка в таблице
  долей), вопрос не показываем, а ответ ставим скриптом — `return autoAnswerIfSingle(Q);` /
  `return autoFillIfSingle(Q, 100);`. Только там, где ответ логически вынужден («чаще всего» из одного
  назначаемого, ранжирование одной компании, доля одной марки = 100%).
  В таблице — по строкам: `row[code].checked = true` + `return answered` (HCP Q14.1: при двух категориях
  «на какую другую категорию» — единственная другая). Ответ, невозможный по прошлым ответам, скрываем
  (`Q.columns.showOnly(...)`: «переход в другую категорию» при одной категории).
- Проверки согласованности с предыдущими ответами — ошибкой с подсветкой строки:
  `resetRowMarks(Q); if (…) return rowError(Q, code, 'Ранее вы сказали, что …');`
- Внутри цикла код итерации берём из `Q.sourceAnswerCode`, а не вычисляем из `Q.number`.
- **Блоки «для каждой категории» разворачиваем генератором в N копий** (`Q7_1`, `Q7_2`, …), а не циклом
  SURVEYSTUDIO: тогда вопросы «для каждого бренда» внутри блока — обычный одноуровневый цикл, имена переменных
  явные. Случайный порядок блоков — `questions.randomizeGroups([[первый, последний], …])` в Подготовке.
- Строки таблиц перемешиваем скриптом в Подготовке `Qxx.rows.randomize()`, а не флагом вопроса
  «Рандомизация» (⚠️ флаг у таблицы может перемешать и колонки-шкалу — не проверено).
- Топ-3 с рангами: множественный выбор ровно 3 (`MinAnswerCount = MaxAnswerCount = 3`) + вопрос
  «Ранжирование» с `Q.showOnly(Qxx.getCheckedCodes())`.
- «Не знаю» в числовых/текстовых таблицах цен — **ввод 0** («Если не знаете цену, впишите 0.»), строки
  обязательные: с пустыми полями респондент может пропустить весь вопрос, не ответив (решение пользователя,
  HCP Perception). В проверках вида «мин ≤ сред ≤ макс» нули не учитываем. Пустое поле = «не знаю» оставляем
  только там, где так договорились (Q3b в Aesthetics v1).
- **Спонтанное → подсказанное знание брендов:** упоминания из открытого вопроса автоматически в подсказанный
  не переносим (никакого сопоставления текста); если врач назвал бренд, которого нет в списке, он сам
  отмечает и вписывает его в «Другое» подсказанного вопроса (решение пользователя, для всех анкет).
- **Одинаковый случайный порядок категорий в двух разделах:** один `randomizeArray([1, 2, 3])` в Подготовке и
  два вызова `questions.setOrderGroups(...)` — для групп раздела 2 и раздела 3 (Aesthetics v2). Циклы
  (`questions.repeat`) создавать после перестановки групп.
- **Вопросы «по брендам с низкой оценкой» (Q11–Q12 Aesthetics v2):** служебный мультивыбор без условия,
